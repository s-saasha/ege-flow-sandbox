# Сверка экранов с API (роль 4)

Для каждого элемента экранов из приложения В ТЗ проверено, есть ли метод в таблице
эндпоинтов (ТЗ, п. 4.1.2). Статусы: **есть** — метод есть и данных хватает;
**уточнить** — метод есть, но в ТЗ не сказано, что он возвращает; **дыра** — метода нет.

## Экран «Вход / регистрация»

| Элемент | Метод | Статус |
|---|---|---|
| Форма входа и регистрации | уходит в сервис аутентификации, не к нам (FR-002) | есть |

| Окно согласия на обработку персональных данных | — | **дыра** (1) |

## Что нужно закрыть до Госприёмки

1. **Согласие на обработку ПДн (дыра).** В ТЗ есть поле `User.consent_at` и правило «до
   согласия доступ закрыт» (NFR-060), но нет метода, который записывает согласие, и нет способа
   узнать, дано ли оно. Предложение: `GET /users/me` (поле `consent_at`) и
   `POST /users/me/consent`; до согласия остальные методы отвечают 403.
2. **Признак «есть вариант ЕГЭ».** В `GET /subjects` нужно поле, например
   `has_exam_variant` (истина, если `variant_structure` не пусто). Иначе клиент не знает,
   показывать ли кнопку.
3. **Статусы и время ответов.** `GET /attempts/{id}` должен отдавать для каждого задания
   `status` и `updated_at` ответа, а метод сохранения ответа — тот же `status` и `updated_at`.
4. **Незавершённые попытки.** В `GET /users/me/attempts` должны быть и незавершённые
   попытки с признаком «не завершена» (пустое `finished_at`) и ссылкой на попытку.
5. **Карточки.** Нужно решить, приходит ли оборотная сторона сразу. Предложение — да.
   Тогда переворот работает без запроса и без задержки.
6. **Счётчик «к повторению».** `GET /topics/{id}/flashcards` должен вернуть число карточек, у
   которых срок наступил (`due_count`). Пустой список «к повторению» — это состояние
   «на сегодня всё».
7. **Формат игры.** В ТЗ не описано, как клиент получает вопросы серии и какие события ходят
   по WebSocket. Предложение: вопросы с вариантами приходят в ответе `POST /game/sessions`
   (без эталона), а по WS клиент шлёт `{"type": "answer", "question_id", "option_id"}`, сервер
   отвечает `{"type": "result", "correct", "score"}`.
8. **Рекорд по теме.** В ТЗ он считается при завершении (FR-055) и отдаётся в статистике
   (FR-061). Для экрана достаточно того, что `PATCH /game/sessions/{id}` вернёт очки и новый
   рекорд, а статистика — рекорды по темам.
9. **Пауза по Esc.** Игровой ввод обрабатывается на клиенте (FR-052). Нужно подтвердить,
   что пауза тоже только на клиенте и сервер её не видит.

Эти пункты — предложения. Если они меняют ТЗ, сначала вносим дополнение по п. 1.8 ТЗ.
